# 原版第一关基准采集流程

状态：采集规范已建立；尚无合格的第一关原版录像、轨迹或固定输入重放。模板文件不作为测试通过证据。

## 版本与起点

1. 运行 `python3 tools/prepare_baseline.py --verify`，确认原始文件未变。
2. 使用 `runtime/game` 或复制到 Windows 的独立游戏副本运行。保留 `original/game` 作为校验基准，不在其中启动。
3. 第一关必须对应 `Levels/Level1.MESHWORLD` 和 `BEGINNERRACE`。EXE 内部类名是 `Board (Warm-Up)`；`Board (Beginner)` 实际对应 Cascade。
4. 用 `python3 tools/new_reference_run.py <会话名>` 创建会话，填写 `session.json`。该工具不会录制或启动游戏。
5. 为该会话记录系统／兼容层、CPU、GPU、D3D8 实现、屏幕与窗口设置、难度、输入设备、控制映射、灵敏度、音量及游戏状态。当前未识别项保持 `null`，不能填推测值。

## 开始前快照

- 保存运行副本中文件清单与哈希，重点检查 `Data/HS.CFG` 等可变文件。
- Windows 原生环境记录 `HKCU\Software\Raptisoft\Hamsterball`；Wine 记录独立前缀中的同一分支。不要备份无关账户或系统注册表内容。
- 记录所选模式、难度、是否镜像、存档、初始关卡和复位点。资源里的 START 标记不等于实测球心状态。
- 若能采集内存，保存初始物理状态、镜头、逻辑时间和随机状态；未定位时明确写“无法采集”。

## 采集顺序

按 `reference/beginner-cases.json` 逐项采集，每项至少重复 3 次。先录制不输入，再录制加速／松手／转弯，最后测试撞墙、跌落、复位、暂停和过关。

每次从相同快照与明确起始事件开始。记录实际输入事件与时间戳，标明时间域是操作系统时间、视频帧号还是游戏逻辑步；在未找到更新循环之前，不把视频帧号当作逻辑步。测试路线须先在原版确认，不提前编造能通关的输入脚本。

视频记录画面、分辨率、帧率和采集起止；音频记录原始播放内容。固定画面比较需要相同状态及分辨率。仅有人工按键录像可以用于视觉研究，不能称为确定性重放。

## 状态与事件记录格式

输入可采用 JSONL：`time_domain`、`timestamp`、`device`、`raw_event`、`focus`、`game_consumed_step`。最后一项未定位时为 `null`。

状态可采用 JSONL：`logic_step`、`logical_time`、`position`、`velocity`、`contact_ids`、`camera_position`、`camera_matrix`、`checkpoint`、`event_ids`、`rng_state`。每个字段须注明坐标／时间单位与采集来源，未采集项为 `null`。

这些是接口约定，目前没有植入或验证原版采集钩子。不得用安卓预览或解析资源产生的坐标补充成“原版轨迹”。

## 第一阶段退出条件

- 原版能稳定进入第一关，画面、输入和声音有实际检查证据。
- 同一基准片段重复运行，已测量原版自身的差异，说明随机性和采样限制。
- 初始配置与可变状态可恢复，文件版本可以校验。
- 输入、逻辑更新时间与状态采集方法已落实，或明确可观测性限制并缩小验收范围。
- 在上述条件满足前，不冻结 60 秒轨迹误差等保真阈值。
