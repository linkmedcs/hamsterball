# 原始资源格式

以下结论来自文件结构解析和交叉校验，未运行原 Windows 程序。全部整数与浮点数采用小端格式。

## 通用结构

- `u32`：32 位无符号整数。
- `f32`：IEEE 754 单精度浮点数。
- 字符串：`u32` 字节长度，后跟包括结尾 NUL 的字节序列；原始名称按 Windows-1252 解码。
- 顶点：8 个 `f32`，依次为位置 XYZ、法线 XYZ、UV。
- 材质：17 个 `f32`（四组 RGBA 与一个光泽值）、一个标志 `u32`、纹理数量与字符串列表。后续材质语义需进一步核实。

## `.meshworld`

1. 标记点数量；每个点包含名称、位置 XYZ、旋转 XYZ、材质列表。
2. 曲线数量；每条包含名称、控制点数量及 XYZ 列表。包括原版 `CameraLocus`，尚未用于运行时镜头。
3. 光源数量；每个包含一个类型 `u32` 与 9 个 `f32`。数值的具体语义仍需核实。
4. 6 个环境 `f32`；当前将前 3 个用作背景色，后三个作为环境光参考。
5. 顶点数量与顶点数组。
6. 八叉树。每节点含 6 个边界 `f32` 与子节点数量；内部节点仅含子节点，叶节点包含材质批次。
7. 每批次包含名称、材质、三角形带数量。每条带含三角形数量与首顶点索引；顶点数量为三角形数量加 2，奇偶三角形交替调整顺序。

已对全部 86 个场景执行文件末尾校验，不存在未消费尾部数据。

## `.mesh`

1. 子对象数量。
2. 每个对象含名称、位置 XYZ、材质及三角形带列表。
3. 每条带含三角形数量，以及 `数量 + 2` 个内联顶点。
4. 全文件末尾为 6 个边界 `f32`，不在每个子对象后重复。

全部 33 个模型均完成严格读取。

## `.cached`

1. `u32 0xBEEF` 与一个版本 `f32`。
2. `u32` 顶点数量与顶点数组。
3. `u32` 索引数量与 `u16` 三角形索引数组。
4. 每个三角形一个 `u32` 分组编号。

全部 100 个缓存文件均完成读取。70 个有对应 world 的缓存，索引总数与 world 三角形带展开结果一致。缓存分组编号尚未映射为运行时事件语义。

## 坐标与运行时格式

安卓端转换为 `(x, y, -z)`，法线同样翻转 Z；纹理坐标保持原值，剔除关闭以支持原版双面面片。

自定义 `.hwa`：ASCII `HWA1`、`u32` JSON 头长度、UTF-8 JSON、连续的展开顶点数组（每顶点 32 字节）。头部记录材质分组长度、标记点、曲线与环境数据。
运行时使用 OpenGL ES VBO，碰撞网格按 XZ 空间划分。

需要继续分析的部分：标记点到动态模型的映射、原版 EXE 中的更新函数、材质渲染状态、碰撞组与事件类型、机关参数及原版物理常数。

## 赛道文件名映射

主赛道配置以原 EXE 的 `Board (...)`、`...RACE` 与资源路径字符串邻接关系交叉核实。特别注意：`Level7` 是 Wobbly，`Level8` 是 Toob，不能直接按照锦标赛中的展示次序给文件编号。
